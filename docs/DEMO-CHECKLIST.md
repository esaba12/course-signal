# Demo Checklist

## 30 minutes before

- Run `python3 audit_data.py`; resolve every failure.
- Run `python3 -m unittest discover -s tests -v`.
- Complete the [visual QA](VISUAL-QA.md) on the laptop used to present.
- Open local dashboard and click CS 124, CS 173, CS 225, CS 233, and CS 374.
- Choose one primary hero course and one backup.
- Confirm the estimate, term count, and backtest are visible.
- If using status data, confirm it is real, cached, and visibly timestamped.
- If not using status data, remove it from the spoken demo rather than explaining a placeholder.

## While presenting

- Start with the public-data limitation; it makes the solution more credible.
- Say “completed-grade headcount,” not “enrollment demand” or “seats.”
- Spend the most time on the backtest.
- End with the governed institutional-pilot path.

## If something fails

- Use the local dashboard rather than a hosted URL.
- If live status fails, continue: historical trend and backtest are the core proof.
- If a course has insufficient history, switch to the backup hero course; never force a number.
