# Two-Minute Hackathon Pitch

## Spoken script

**Problem — 20 seconds**

“Course planning conversations often start from anecdotes: a class felt crowded or a section closed quickly. But public schedule data does not provide numeric capacity, so we refused to fake a seat-crunch metric.”

**Insight — 20 seconds**

“Instead, we use publicly released UIUC course data to show the number of students who received a final grade in each course and term. It is a historical planning signal, not direct demand—and the product says that clearly.”

**Demo — 45 seconds**

“Here is CS 225. We compare Fall to Fall, so we are not mixing a summer section with a large fall lecture. The estimate is based on [N] prior Fall terms. More importantly, this backtest shows what the same method would have predicted before a known past term happened, versus what actually occurred.”

**Current context — 15 seconds**

“Where a verified Course Explorer snapshot is available, we add the latest Open/Closed view and the retrieval time. It is a cached snapshot, not continuous monitoring.”

**Path — 20 seconds**

“The hackathon wedge proves a transparent workflow on public data. The institutional path is a governed pilot: first learn planners’ decision moments, then—with approval—integrate capacity, registration, waitlist, cross-listing, room, and staffing context. The dashboard remains decision support, not an autonomous decision-maker.”

## Do not say

- “We predict capacity.”
- “We know demand.”
- “The model tells departments what to cut.”
- “The open/closed status tells us how full a class is.”

## Evidence to have on-screen

- The comparable-term chart.
- Estimate plus number of historic terms.
- Latest backtest prediction, observed value, and error.
- Public-data/source framing.
- Cached-status timestamp only when a real verified snapshot is loaded.
